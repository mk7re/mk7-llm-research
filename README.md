# mk7-llm-research

Research environment for reverse engineering Mario Kart 7, meant to be driven by a human together with an LLM agent.
The research results themselves are the `template/` files of the main repository; this folder holds the tooling and
the notes that help produce them.

Agents read this file fully at the start of every session, then only the documents the task needs: the
[document map](#document-map) says which, and every document opens with a contents list to pick sections from.
What is already known about the game is indexed in [docs/research/INDEX.md](docs/research/INDEX.md).

## Contents

- [Rules of the workspace](#rules-of-the-workspace): what the agent may and may not do; always applies
- [Document map](#document-map): which document to read for which task, and the index of reviewed research

## Rules of the workspace

This workspace is meant to be used as a git submodule of [MK7-Memory](https://github.com/mk7re/MK7-Memory), checked out
at `mk7-llm-research/`. "The repository" below means that parent repository.

1. **The repository outside `mk7-llm-research/` is the product.** Research findings end up as edits to `template/`.
   Tooling, scripts and notes stay inside `mk7-llm-research/`.
2. **`template/` stays pristine.** The agent never edits it. Template changes are made on a copy under
   `mk7-llm-research/local/work/` and delivered as `.patch` files ([PATCHES.md](docs/tooling/PATCHES.md)).
3. **No committed copies of the generated headers.** Headers are generated by the repository's `make` into
   `<repo>/include` (git-ignored), or, for a template copy, next to that copy inside `mk7-llm-research/local/`. Nowhere
   else.
4. **Folders named `local` are never committed; everything else is.**
   - `<repo>/local/` holds what the user provides: game binaries, symbol maps and RomFS files (copyrighted, never
     commit them), and the [session input files](docs/tooling/WORKSPACE.md#session-input-files).
   - `mk7-llm-research/local/` holds intermediate files (caches, the Ghidra project, decompiler output, template work
     copies, extracted game data, the Python environment). It can be deleted at any time.
5. **The agent never commits.** No `git commit`, `git push`, or anything else that records or publishes changes. A
   human reviews and commits every change.
6. **Research is reviewed three times before it counts.** Results land in `pending-verification/`, move to `final/`
   after two reviews by the agent (first the facts, then the document), and reach `docs/research/` only after a human
   has reviewed them. Every step of the agent starts with a context reset: the research, the fact check and the
   document review. See [WORKFLOW.md](docs/tooling/WORKFLOW.md).
7. **New tooling needs the user's agreement first.** The agent explains what it wants to build and why, and waits for
   a yes. Bugs in the existing tooling are fixed without asking; the agent says so.
8. **Work step by step.** The agent proposes, the human decides.
9. **This is a shared project.** Everything committed is written for anyone who clones it, with no facts about one
   person's setup ([Shared-project rule](docs/tooling/DOCUMENTING.md#shared-project-rule)).
10. **Tooling and its documentation change together**, following [DOCUMENTING.md](docs/tooling/DOCUMENTING.md):
    contents lists, short main documents, examples and measurements only in subdocuments, and argument tables that
    cover every argument.
11. **Only `eur2` (v1.2) is documented.** The other builds are references; offsets, sizes and behaviour are confirmed
    in `eur2` ([Which build is documented](docs/tooling/WORKSPACE.md#which-build-is-documented)).

## Document map

The workspace's documents are in `docs/tooling/`; reviewed research is in `docs/research/`. Subdocuments are listed
under their main document, which routes to them in more detail.

| Document | Read it when |
| --- | --- |
| [WORKSPACE.md](docs/tooling/WORKSPACE.md) | you need to know which build is documented and what the others are for, where a file or folder lives, or the user mentions a file they provided |
| [SETUP.md](docs/tooling/SETUP.md) | setting up a fresh clone, or a tool, binary or environment variable is missing |
| [CLI.md](docs/tooling/CLI.md) | using the `mk7` CLI: which command group does what and what it needs, known caveats |
| ↳ [cli/templates.md](docs/tooling/cli/templates.md) | arguments of `struct`, `field`, `find`, `gaps`, `gen`, `verify` |
| ↳ [cli/binary.md](docs/tooling/cli/binary.md) | arguments of `images`, `sym`, `dis`, `xref`, `vtable`, `read`, `strings`, `access`, `port`, `diff`, `ghidra`, `decomp` |
| ↳ [cli/gamedata.md](docs/tooling/cli/gamedata.md) | arguments of `romfs`, `kmp`, `bseq` |
| ↳ [cli/emu.md](docs/tooling/cli/emu.md) | arguments of every `mk7 emu` command |
| [GAME_DATA.md](docs/tooling/GAME_DATA.md) | the task involves the game's data files (RomFS, `.szs`, KMP, BSEQ) |
| [EMULATOR.md](docs/tooling/EMULATOR.md) | something has to be checked in the running game (Azahar, `mk7 emu`): setup, the rules of a session, what the commands can do |
| ↳ [emulator/menus.md](docs/tooling/emulator/menus.md) | getting to a course or a page: which run to use, the course and button table, how buttons are pressed, the character, kart and settings pages |
| ↳ [emulator/races.md](docs/tooling/emulator/races.md) | working during or after a race: ending races, carrying a run on, the race page's menus, the player's kart driven by the AI |

| ↳ [emulator/library.md](docs/tooling/emulator/library.md) | writing a Python script against the running game, adding a reader or command; where game state is read |
| ↳ [emulator/hooks.md](docs/tooling/emulator/hooks.md) | changing the hooks, the code pages or the boot patches; a command fails around boot, freezing or saving |

| [WORKFLOW.md](docs/tooling/WORKFLOW.md) | doing a research pass (research, fact check, document review) |
| [WRITING.md](docs/tooling/WRITING.md) | writing or reviewing a research topic document |
| [PATCHES.md](docs/tooling/PATCHES.md) | research changes `template/`, or a patch has to be checked |
| [DOCUMENTING.md](docs/tooling/DOCUMENTING.md) | changing the tooling or any document of `docs/tooling/` or this file |
| [docs/research/INDEX.md](docs/research/INDEX.md) | starting any research task: what is already known and reviewed, one line per subject |
